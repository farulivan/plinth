# Media: same-origin variant URLs from self-contained fields, digest-signed uploads

Two shapes [ADR-0006](./0006-media-pipeline.md) left open. First, delivery: rendered pages reference variants as same-origin paths — `/_media/{contentHash}/w{width}.{format}` — resolved by whichever origin serves the page (the worker-router maps them into the media bucket under the hostname's workspace; the dashboard proxies the identical path through the api for previews, thumbnails, and the library). To make that derivable everywhere, the `mediaRef` field freezes `{contentHash, width, height}` alongside `{mediaId, alt}` at pick time — variants are content-addressed and immutable, so a snapshot is self-renderable with zero media-table reads at build or preview time. Second, upload signing: multipart bodies ride the internal HMAC envelope with `sha256(body)` in the canonical string's body slot, carried in `x-plinth-body-sha256`; the verifier recomputes the digest from the raw bytes, so binary payloads never round-trip through text decoding and stay tamper-proof.

## Considered options

- **Same-origin `/_media` paths + self-contained fields (chosen).** The renderer needs no base URL and no environment — packages stay env-free per the repo convention, snapshots frozen in one environment render identically in every other, tenant isolation is enforced by the origin (a hostname can only reach its own workspace's objects), and the tenant CSP's `img-src 'self'` already covers it. Cloudflare's edge still fronts every production byte; the worker is simply the CDN's origin, with `immutable` caching on content-addressed paths.
- **Absolute CDN URLs stored in fields or resolved via env — rejected.** Frozen absolute URLs rot across environments (a local MinIO URL inside a production snapshot); env-resolved bases require threading configuration through an intentionally pure renderer to every `MediaRef` call site, or a global mutable that bleeds across concurrent preview requests.
- **A media manifest passed alongside the document (id → hash lookup at render) — rejected.** Keeps fields minimal but makes every renderer consumer (preview, builder, future template tests) fetch and thread a lookup table for data that is immutable anyway; denormalizing three immutable scalars is strictly simpler.
- **Signing raw multipart bytes in the HMAC body slot — rejected.** The canonical string is UTF-8; binary bodies would be decoded, mangled, and unverifiable. Exempting the body entirely was rejected too — an unsigned body is a writable hole through the internal seam. The digest variant keeps the guarantee at one hash's cost.

## Consequences

- `resolveImageUrl(contentHash, width, format)` is the one URL rule, and `mediaVariantWidths()` (shared schema helper) is the one existence rule: the upload pipeline emits exactly the widths ≤ the original (never upscaling), and the renderer's `srcset` derives from the same function — no drift by construction.
- The dashboard's `/_media/[contentHash]/[variant]` proxy authenticates (session + the api's workspace-scoped lookup) and caches `private, immutable`; the worker's is public `immutable`. Draft images are therefore exactly as public as ADR-0006 already accepted: guessable only with the full content hash.
- **Trade-off accepted: a field's frozen `width`/`height` describe the original at pick time.** Re-uploading a different image produces a different hash and a new pick; there is no path where the stored dimensions drift from the stored bytes.
- **Trade-off accepted: `/_media` is a reserved path prefix on tenant sites.** A template page named `_media` would be shadowed; the underscore convention marks it internal, and the builder controls page names until templates do — revisit if a template ever needs the name.
- The upload forwarder is a Next route handler, not a Server Action — actions buffer through the RSC transport with a small body budget. Multipart exists only on the browser→dashboard leg: the forwarder unwraps the file and sends raw bytes internally, so the signed digest IS the file's content hash and no multipart parser sits behind the trust boundary.
